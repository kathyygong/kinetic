# Insights caching and model evaluation

Implemented and checked locally on September 14, 2026. No hosted account was
created, no paid inference was enabled, and no public deployment was performed.

## Fixed recruiter demo

The Insights screen reads an exact-match synthetic artifact generated by real
model calls: Llama 3.2 3B for scheduling selection and Qwen3 8B for training-response
comparisons. The artifact includes the raw model proposals, validated results,
model/provider, generation timestamp, canonical inputs and model/verifier source
hashes. It contains no real runner data or credentials.

The main cards omit AI/deterministic badges and address the user directly.
Evidence details identify the model, generation time and **Precomputed sample**
delivery. Analyze/refresh reuses that sample; it
does not pretend to make a live inference call or substitute rule-generated
insights. Changed sample inputs fail closed. Plan previews and confirmation are
rebuilt from the current plan, never stored as cache actions.

The artifact generator replays each recorded model proposal through the current
verifier before writing. Its verify mode detects changed inputs, source versions
or result tampering. The standalone frontend build also checks exact inputs,
source hashes, contracts and provenance before producing output. These are trusted
build artifacts, not independently signed attestations of external submissions.

Insights therefore works after model inactivity or an inference outage. Today
and natural-language intake still need the backend; intake's existing fallback
policy is unchanged. This does not make the entire app offline or production-ready.

## General Kinetic cache

Authenticated behavior/discovery endpoints cache **validated model proposals**,
not workouts, recovery scores or final plan mutations. Each request still computes
current evidence and review eligibility. The old daily-reasoning cache remains
disabled; training-summary generation and current safety decisions are unchanged.

- Keys include the authenticated owner's namespace, exact input, generated prompt,
  system prompt, output schema, model/provider/endpoint, inference settings and
  verifier version. Discovery includes the held-out history and assessed date,
  not only the subset shown to the model.
- New outcomes, missing data, corrected history or changed model/verifier context
  cause a miss. There is no fuzzy or cross-runner semantic reuse. If future prompts
  consume goals, readiness or plan context, those inputs must also enter the key.
- Cached comparisons are reverified on every hit. Discomfort and disabled-mode
  checks run first. Valid empty selections and no-finding comparisons may be
  reused; malformed responses and transport failures are never stored.
- Values contain selected IDs or comparison requests and generation time. Input
  histories and raw notes are not stored in this process cache. Hashes are not
  encryption or a substitute for authorization.
- The cache has 128 entries, a one-hour lifetime, a 64 KiB value cap and at most
  16 concurrent keyed generations. Identical in-flight calls share a result;
  waiters have a 20-second bound. Expiry is enforced on reads; expired memory is
  reclaimed on subsequent requests, eviction, deletion or process restart.
- Account cleanup evicts the authenticated owner's entries before and after the
  cleanup attempt, including retryable failures. In-flight work cannot repopulate
  an evicted entry. Other owners remain isolated.
- Unauthenticated custom requests do not share a cache. The public synthetic demo
  uses its separate immutable build artifact, not an anonymous personal namespace.

**Deployment limit:** this first implementation is process-local, matching the
current single-worker backend. Before running multiple workers/replicas with
personalized caching, use a shared owner-scoped store or invalidation channel and
test deletion across workers. Process-local eviction cannot clear another worker.
Strict authentication, public request limits and provider spending controls remain
release requirements. This cache is not an authorization, request-throttling or
distributed storage system.

## Hosted model option

Groq's SDK is installed and an Insights-only route is available. API keys stay on
the backend. Existing intake routing remains unchanged. For the current runtime
gate, enable AI rather than `fallback`/`disabled`, then set:

```dotenv
KINETIC_AI_MODE=local_ollama
KINETIC_DEMO_MODE=false
KINETIC_INSIGHTS_PROVIDER=groq
INSIGHTS_MODEL=openai/gpt-oss-20b
DISCOVERY_MODEL=openai/gpt-oss-20b
GROQ_MAX_COMPLETION_TOKENS=1536
```

Set `GROQ_API_KEY` directly in the local ignored environment file or deployment
secret manager. Never put it in frontend configuration or committed files. A key
was subsequently configured privately and the hosted candidate was live-tested.
The results below do not yet justify switching the demo's existing model choices.

The adapter uses strict JSON schemas with required nullable fields, low reasoning
effort for GPT-OSS, a bounded output budget and a 15-second application deadline.
It rejects incomplete responses and strips provider error bodies from surfaced
errors. SDK retries are disabled; only one immediate retry for 502/503/504 is
allowed within the remaining deadline. Rate limits and authentication failures
are not blindly retried. Mocked SDK checks are not hosted latency/quality evidence.
Groq rejects the `uniqueItems` schema keyword, so the provider payload omits it;
Kinetic still validates duplicate IDs locally. This compatibility fix was verified
with both mocked requests and a successful live scheduling response.

## Measured comparison

Local models: one live repeat per case, cache disabled and warmed separately.
Hosted results combine a quota-limited two-pass burst with focused follow-up cases:

| Candidate | Passing cases | Median | Slowest | Outcome |
| --- | --- | --- | --- | --- |
| Local Qwen3 8B | 5/5 | 12.086 s | 13.477 s | Retain for discovery |
| Local Llama 3.1 8B | 4/5 | 11.531 s | 13.256 s | Invalid comparison output on improving history |
| Groq GPT-OSS 20B | 4/5 distinct cases | 0.500 s* | 1.698 s* | Improving-history JSON failure; burst quota limits |

The first hosted burst after the schema fix produced four passing responses and
six HTTP 429 quota failures. Focused follow-up passed failed-later-corroboration,
but improving history returned HTTP 400 `json_validate_failed`. Scheduling,
the recovery concern, flat history and failed later corroboration have passed;
the full two-repeat suite has not. The API reported an 8,000-token limit in its
rate-limit headers. No subscription or provider routing was changed.

*Hosted timings include only the five validated responses, including two
scheduling runs. They exclude quota and JSON-generation failures; they are not
end-to-end availability statistics or directly comparable controlled performance
measurements. A paid tier may raise quotas but would not establish that the
structured-output failure is fixed. See the separate
[hosted benchmark report](docs/insights-hosted-benchmark.json).

Cases cover scheduling, the sustained recovery concern, flat response, improving
response and failed later corroboration. False model hypotheses on flat data were
discarded by the verifier. This small run is not an availability guarantee,
statistical model ranking or clinical evaluation. See the machine-readable
[benchmark report](docs/insights-model-benchmark.json).

In the browser, three cached demo refreshes took 44, 50 and 74 ms with zero Insights
API requests while those requests were blocked. This measures interaction-to-result
in the local browser, not cold page download or a hosted-service percentile.
A separate real backend discovery call took 8.66 seconds; the subsequent
owner-scoped cache hit took 4.8 ms with the same freshly verified finding.

## Commands

Use Python 3.12 with the backend requirements and installed frontend dependencies.
From the repository root:

```bash
PYTHONPATH=backend python -m evals.insights_cache_smoke
PYTHONPATH=backend python -m evals.hosted_insights_smoke
PYTHONPATH=backend python -m evals.insights_benchmark_smoke
PYTHONPATH=backend python -m evals.demo_ai_artifact_smoke
PYTHONPATH=backend python -m evals.generate_demo_ai_cache --verify
PYTHONPATH=backend python -m evals.benchmark_insights_models --repeats 2
PYTHONPATH=backend python -m evals.benchmark_insights_models --candidate groq/openai/gpt-oss-20b --repeats 2 --output docs/insights-hosted-benchmark.json
PYTHONPATH=backend python -m evals.generate_demo_ai_cache
npm --prefix frontend run demo:check
npm --prefix frontend run demo:build
```

Generation replaces the artifact only after successful model calls and validation.
The benchmark now stops at the first HTTP 429, records safe quota headers, and
excludes failed generations from latency statistics. Use `--case` to select a
missing case and `--append` to preserve earlier attempts after quota is available;
it does not loop on rate limits or silently upgrade the account.
To seed with a tested hosted model, pass `--provider groq --model
openai/gpt-oss-20b --discovery-model openai/gpt-oss-20b`. Benchmark it first; changing
the provider does not automatically establish acceptable quality or reliability.
